# Photographed scan fixtures

This directory is reserved for real Android camera captures and must not be modified by the synthetic fixture generator.

The authoritative metadata file is `manifest.json`. It intentionally starts with no fixtures or comparison pairs. An empty manifest is valid evidence that production duplicate/revision thresholds are still unavailable; it must never be replaced with synthetic measurements or guessed values.

## Required evidence per fixture

Each fixture must preserve both:

1. the immutable raw Android camera capture, and
2. the upright, contrast-normalized OCR PNG produced by the production Rust scan pipeline from that capture.

The manifest verifier requires:

- source description, explicit consent, license, and attribution,
- Android manufacturer, model, OS version, and build fingerprint,
- camera ID, lens direction, and capture resolution,
- capture timestamp, lighting, distance, angle, stabilization, and notes,
- A2D page identity, physical-sheet identity, content-revision identity, print source, paper, and writing instrument,
- raw and normalized relative paths, byte lengths, and lowercase SHA-256 digests,
- normalized pipeline version and an explicit upright rotation of zero degrees.

Raw photographs must not be retouched, cropped, perspective-corrected, or contrast-adjusted. The normalized OCR PNG is a derived fixture and must be generated by the same Rust processing policy used for scan registration.

## Labeled comparison pairs

Every comparison pair targets the same A2D page identity and uses one of these labels:

- `near_duplicate`: independent photographs of the same physical sheet at the same content revision,
- `revision`: the same physical sheet photographed before and after additional writing,
- `substantially_different`: the same page identity with materially different content or physical-sheet provenance.

The verifier rejects self-comparisons, missing fixtures, duplicate unordered pairs, inconsistent labels, path traversal, hash drift, and incomplete provenance.

## Validation and measurement

Validate provenance and immutable files:

```text
python tools/verify_photographed_scan_fixtures.py
```

After photographed fixtures and labeled pairs exist, emit a validated, hash-checked input file and then run the authoritative Rust fingerprint measurement:

```text
python tools/verify_photographed_scan_fixtures.py \
  --calibration-input target/photographed-fingerprint-input.tsv

cargo run -p a2d-image --features fixture-tools \
  --bin a2d-fingerprint-calibration -- \
  fixtures/scans/photographed \
  target/photographed-fingerprint-input.tsv \
  target/photographed-fingerprint-calibration.tsv
```

Both output files use create-new semantics and refuse to overwrite an existing report. Remove or archive an earlier output explicitly before rerunning.

The calibration report contains mean and maximum absolute difference, nonzero-cell count, nearest-rank percentiles, the complete 256-bin difference histogram, and every per-cell absolute difference. It does not select a threshold or return a duplicate/revision classification.

Production thresholds may be proposed only after the photographed corpus covers multiple supported Android device tiers and representative lighting, angle, distance, focus, glare, and writing conditions. The proposal must cite the exact manifest and generated report revision, document false-positive and false-negative tradeoffs, and remain reviewable rather than becoming a hidden default.
